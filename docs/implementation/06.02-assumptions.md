# Phase 06.02 implementation assumptions

Status: accepted engineering assumptions for Shared Infrastructure. These do not override higher-ranked product specifications.

## Persistence boundaries

- PostgreSQL is authoritative. Redis is limited to rate-limit state and event wake-up/fan-out.
- `analyses` and transcript spine tables are introduced as parent skeletons because shared findings, spans, stage runs, flags, authorization, and events require real foreign keys. Submission and transcription behavior remains deferred to F1/F2.
- `analysis_events` is added because resumable monotonic SSE requires durable replay history. Event sequences are contiguous per analysis, assigned under a PostgreSQL advisory transaction lock, retained for a configurable bounded period, and represented as decimal strings on the wire.
- The initial deferred traceability trigger enforces span-or-insufficient. F6 must replace/extend the function in its migration to accept only verified `finding_evidence` as the evidence alternative.

## Identity and authorization

- External OIDC credentials are exchanged for stateless, eight-hour HS256 application sessions. No speculative session table is introduced.
- Deleted users resolve as anonymous. Logout remains idempotent so stale, expired, or deleted-user cookies can still be cleared. An email already bound to another provider subject is a conflict and is never silently relinked.
- Owner authorization is deny-by-default and centralized. Share principals do not pass owner checks.
- Origin checks protect cookie-mutating routes. Production deployment must preserve the original client address in a trusted `X-Real-IP` or sanitized `X-Forwarded-For` header for anonymous rate limiting.

## Operational policy

- Rate-limit class values are provisional and configurable: A=10/hour, B=120/hour, C=600/hour, D=30 concurrent streams, P=120/hour. Phase 07 must calibrate values; the class mechanism is stable.
- Stream leases expire and renew so disconnected processes cannot hold permanent concurrency slots.
- Replay retention defaults to 24 hours and 1,000 events per response. Expired, future, discontinuous, or oversized cursors emit `RECONCILE_REQUIRED` so clients fetch authoritative state.

## AI safety

- Source delimiter collisions are neutralized in the prompt copy by replacing the first `<` in a colliding delimiter with full-width `＜`. This preserves JavaScript string length and transcript offsets while preventing source-controlled closure of the wrapper.
- Suspicious-instruction detection is deterministic telemetry, not a truth classifier. Source content remains data even when no signal is detected.
- Every model stage must use the shared strict Ajv registry and bounded retry runner. Exhausted schema retries fail closed; no unvalidated output is returned.
- S9 removes invalid span/evidence references and emits only anchored findings or explicit `insufficient` findings. Public serialization strips raw confidence.
- Until Phase 07 calibration, every named-person finding requires XC verification. A negative named-person finding additionally requires at least two independently verified attached evidence sources; failure converts the item to `insufficient` rather than asserting a verdict.

## Deliberate deferrals

- No per-kind finding tables, evidence/source tables, feature endpoints, upload/worker behavior, privacy feature behavior, or frontend redesign is included in 06.02.
- Live Debate remains scheduled after the upload pipeline.
