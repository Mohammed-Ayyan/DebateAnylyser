# F1 Multi-format Ingest — implementation assumptions

Date: 2026-07-27

## Contract amendments

- Upload presign requests also require `rights_basis` and `intended_use`; analysis creation requires the same declarations. URL submissions additionally require `access` and `retrieval_method`. These fields make F1a enforceable rather than inferred.
- Accepted-use consent is read from the authenticated account. Clients cannot assert a policy version in an analysis request.
- Uploads allow exact extension/MIME pairs only: TXT/text, PDF, DOCX, MP4, MP3, and WAV. The default maximum is 500 MiB. Paste defaults to 1,000,000 Unicode code units. Both limits are configurable.
- Upload filenames are reduced to a normalized basename, stripped of control characters, and capped at 255 characters. Object keys are generated by the server and owner-scoped.
- URL submissions are queued without fetching. F2 owns retrieval/transcription; F1 only validates the envelope and F1a authorization metadata.

## Durability and security

- PostgreSQL is the queue authority. Analysis, optional paste input, upload claim, job, and idempotency response are committed atomically.
- `201 Created` is returned only after the queued job exists in the same committed transaction.
- Upload objects are verified with `HeadObject` for owner metadata, exact size, and content type before the reservation can be claimed. Reservations are expiring and single-use.
- `Idempotency-Key` is hashed at rest. A transaction-scoped PostgreSQL advisory lock serializes concurrent retries; reuse with a different normalized request returns `409`.
- Rights gating runs before object inspection, URL access, analysis persistence, or job creation. A blocked request creates no analysis or job.
- Pasted text remains untrusted input in `analysis_inputs`; it is not a transcript and is never interpreted as instructions.

## Operations

- Object storage uses the S3 API and supports AWS or a configured S3-compatible endpoint. Bucket configuration is required only when upload endpoints execute.
- Worker claims use `FOR UPDATE SKIP LOCKED`, renewable-by-reclaim leases, and opaque lock tokens. F1 does not execute F2 or transcribe content.
- Expired upload reservations, unclaimed objects, and expired idempotency rows require scheduled cleanup in deployment operations. The storage adapter exposes deletion for this purpose.
